# Changelog

All notable changes to Watch Party Manager are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [Unreleased]

### Added

- `/random watch` (a grouped subcommand -- see Changed, below, for the rename from `/random_watch`): pick one random eligible watch item from a collection, for a group that can't decide. Collection selection matches `/list` (automatic from thread context, a picker otherwise, always with a **Change Collection** option); the collection picker and **Add Filters** screen are always private (ephemeral), visible only to the member running the command. The default **Pick Random Item** action chooses uniformly at random from the collection's Eligible Pool -- deliberately bypassing the collection's configured Nominee Selection mode entirely, so it is never Favor New/Older Additions-weighted. Once an item is actually found, the result is posted **publicly** in the channel for the whole group to see (the private screen that triggered it is replaced by a brief private hand-off note); **Pick Again** rerolls that same public message in place, with immediate repeats permitted (no hidden no-repeat state), and only the member who ran `/random watch` may use Pick Again/Change Filters/Change Collection -- anyone else gets WASH's standard "only the person who ran this command" message. Change Filters/Change Collection clicked from the public result each open a fresh private follow-up screen (a public message can never be edited into a private one); a new item found from that follow-up is posted as its own new public result. An optional **Add Filters** screen reuses the shared filter-menu architecture (below) to narrow the random pool, for that session only, by Genre, IMDb Rating, MPAA Rating, Actor, and/or Suggestion Source (Member); active filters are shown in a scalable **Current Filters** bullet list, preserved across Pick Again, and never affect the collection's or guild's own configuration. An empty filtered pool explains the active collection and filter(s) rather than failing generically. The result reuses WASH's existing suggestion presentation (title, year, poster, genre, IMDb link, original suggester, and a link to the original suggestion post when available), always states the pick was random, and offers **Pick Again**, **Change Filters**, **Change Collection**, and (when available) **View Original Suggestion**. A discovery tool only -- it never starts a voting round, changes a suggestion's status, marks anything watched, or changes any collection setting.
- A [Troubleshooting Guide](docs/12-Troubleshooting.md) (`docs/12-Troubleshooting.md`) -- the administrator's first stop when something goes wrong, grouped by area (Installation, Setup Wizard, Configuration, Voting, Crew Review, Backups, Discord, and General log-reading/bug-report guidance), pointing at the relevant section of the Administration Guide, Installation Guide, or Command Reference rather than duplicating them.
- Custom Vote Filters and `/random watch`'s Add Filters now share one filter-editing experience -- Genre, IMDb Rating, MPAA Rating, Actor, and Member (Member always last), each optional and independently resettable to "Any", applied in that fixed order to narrow the eligible pool before Random Watch's true-random pick or Custom Vote's Nominee Selection strategy runs. `/vote start` -> **Customize This Vote**'s **Edit Filters** button (and `/random watch`'s **Add Filters**/**Change Filters**) opens a shared filter menu (`filter_menu_view.py`, wired up by `bot.py`'s `create_filter_menu_session`) rather than inline dropdowns, since five filters plus the primary action can't fit in Discord's 5-action-row limit on one screen; each filter gets its own small edit screen (or, for IMDb Rating and Actor, a modal) and always returns to a refreshed menu showing the current selections. **Genre** and **MPAA Rating** are dropdowns built from ratings/genres actually present in the collection's eligible pool (MPAA Rating always lists "Any MPAA Rating" first, case-insensitive matching, "Not Rated" and "Unrated" kept distinct since OMDb uses them for different things). **IMDb Rating** accepts an optional minimum and/or maximum (0.0-10.0, one decimal place, both inclusive, min may not exceed max) via a small modal, with its own "Any IMDb Rating" reset. **Actor** is a searchable text field, not a capped dropdown -- typing part or all of a name matches against every suggestion's stored cast list (case-insensitive); one clear match applies immediately, multiple matches show a disambiguation picker (capped at 25 with a "refine your search" note if more matched), and no matches shows a clear warning without leaving the filter flow. Every filter treats a suggestion with no stored value for that field as never matching while the filter is active, but fully eligible when the filter is set to Any -- filtering only ever reads already-persisted IMDb metadata (never a live lookup while opening the menu or starting a vote). **Member** (`services/member_filter_validation.py`) is unchanged from its previous behavior: e.g. for a birthday vote, with no profile or birthday record required; a valid member is the server owner, a WASH Crew member, or a current Watch Party member with at least one eligible suggestion, an invalid selection shows a highly visible ⚠️ warning and blocks continuing until resolved, and bots are judged by the same rules as anyone else. All five filters are built on the same reusable `NomineePoolFilter`/`FilteredCandidateSelectionStrategy` architecture (`services/nominee_pool_filter.py`) that narrows a candidate pool before selection runs, with zero changes to `VoteService` or `NomineeSelectionService`, and a scalable **Current Filters** bullet list (inactive filters shown as "Any X", omitted from final displays) shared unchanged by both flows. An insufficient filtered pool blocks round creation (Custom Vote) or explains itself with a way to change filters (Random Watch) rather than ever pulling from outside the filtered pool. Neither flow ever saves a filter to the collection's or guild's own configuration. Submitting Customize This Vote's modal shows a **Review This Vote** summary (collection, Nominee Selection, Vote Visibility, candidate count, duration, and any active filters) with **Start Vote**/**Cancel** before the round is created. Active filters (and which Nominee Selection mode a round actually used) are shown in the voting post, `/vote status`, and the results announcement, and survive a bot restart; legacy `VoteRound` records saved before IMDb Rating/MPAA Rating/Actor existed continue to load with those three filters defaulting to inactive.
- `cast` (actor names) is now captured and persisted alongside a suggestion's other IMDb-derived metadata (`WatchItem.cast`, parsed from OMDb's `Actors` field), enabling the Actor filter above. Existing suggestions added before this change simply have an empty cast list (never a crash) until re-added or otherwise refreshed; there is no automatic bulk re-fetch of already-suggested items' cast data (see "IMDb Rating, MPAA Rating, or Actor filter has no options / never matches" in `docs/12-Troubleshooting.md`).
- `/config` -> **Voting Defaults** now also exposes **Nominee Selection**, mirroring the Setup Wizard's own Voting Defaults step -- previously it was only reachable through `/config` -> Collections, an inconsistency with how Setup presents the two together. A server with exactly one collection resolves it automatically and preselects its current mode; a server with more than one is asked which collection's Nominee Selection to edit first. Saving updates Nominee Selection on the selected collection only -- Vote Visibility, candidate count, and vote duration continue to save guild-wide, as before. The Voting Defaults modal itself is unchanged (candidate count and duration text fields only; Discord modals cannot contain selects).
- Automatic, scheduled backups: enable (the default and recommended setting) or disable them from the Setup Wizard's Backup step or `/config`'s Backup Defaults. While enabled, WASH creates a backup on the configured interval and prunes older automatic backups down to the configured retention count, independently of any manual backups kept. Disabling stops future automatic backups without deleting existing ones, and manual `/backup` remains available regardless of the setting. Re-enabling resumes scheduling from the saved or newly configured interval/retention, and the schedule is reconciled against the saved configuration on every startup as well as immediately after any `/setup` or `/config` change.
- A guided Change End Time flow for `/voting edit`: **End Now**, **Shorten Vote**, **Extend Vote**, and **Set Exact End Time**. Shorten/Extend each offer 1 Hour, 1 Day, or a Custom... duration, applied relative to the round's *current* end time (never to "now"); Set Exact End Time accepts a single pasted Discord timestamp (e.g. `<t:1785639600:F>`, generated by typing `@time` in any normal Discord message box). Every deadline is still stored and scheduled internally as UTC.
- One shared duration syntax used everywhere WASH accepts a relative duration -- vote duration, reminder-before-close, and Shorten/Extend Vote: a whole number immediately followed by a unit (`m`/`h`/`d`/`w`, or the words `minute(s)`/`hour(s)`/`day(s)`/`week(s)`). A bare number with no unit is no longer accepted.
- Reminder-before-close now supports minute precision (e.g. `10m`, `30m`), not just whole hours.
- Vote duration itself now supports the same minute precision as reminder-before-close and Shorten/Extend Vote (e.g. `10m`, `30m`), not just whole-hour amounts -- Guild Configuration's/a collection's configured default duration is minute-based too, with older hour- or day-based values loading as the exact equivalent minute count.
- Voting posts and announcements (opened, reminder, closed, results, cancelled, deadline-changed) are now centered on the collection's name (with a built-in emoji for standard collections -- Movies, TV Shows, Anime, Holiday, Documentaries, Horror), e.g. "🎬 Movie Suggestions Voting Is Open", with the round number shown as secondary information (`Round: 3`).
- `/reject`'s confirmation now links back to the suggestion's original public post (when it has one) and includes an **Undo Rejection** button, restricted to the rejecting member, that immediately removes the rejection and refreshes the post's rejection count.
- `/setup` now begins by asking where WASH should create its home channel (a new channel, default name "Watch Party", or an existing one). Every collection's suggestion thread, and by default the Watched Item Archive thread, is created as a sibling thread under this one channel -- collections default to threads rather than separate channels. Movies/TV Shows now default to the more descriptive thread names "Movie Suggestions"/"TV Suggestions" (custom names remain fully editable for every collection type).
- A four-status suggestion model -- 🟢 Available, 🟡 Rotation Cooldown, 🟣 Vote Winner, 🔴 Retired -- replacing the old, never-actually-produced Watched status. Vote Winner is now set automatically when a voting round completes. Rotation Cooldown is computed at display time and automatically reverts to Available once a fresh rotation begins.
- A Status field on every suggestion's public confirmation post, kept synchronized in place (never recreated) whenever the suggestion's status changes.
- `/database move`: move a collection's suggestion destination to a different channel or thread (via Create New Thread, Use Existing Thread, or Use Existing Channel), without touching anything else about it -- the collection's database ID, suggestions, statuses, vote history, rotation history, statistics, and every other setting are all preserved, and existing Discord suggestion posts stay exactly where they are; only suggestions added after the move post to the new destination. A failure after creating a new thread automatically deletes it rather than leaving it orphaned.
- A configurable, per-collection "I Won't Watch" system: it can be enabled (the default) with a threshold (default 2, range 1-10) -- the number of distinct members who must press "I Won't Watch" before a suggestion needs WASH Crew review -- or disabled entirely. It now has its own dedicated Setup Wizard step (immediately after Voting Defaults, with its own Enable/Disable button choice before asking for the threshold) and its own numbered `/config` section ("I Won't Watch" Settings), separate from Voting Defaults -- a server with one collection edits it directly; more than one requires choosing which collection first, exactly like Nominee Selection. While disabled, a suggestion's public post omits the "I Won't Watch" button entirely (not just disables it) and `/reject` refuses with a clear message; no new rejection is ever recorded, but existing rejection history is preserved, and re-enabling never retroactively re-evaluates an existing below-threshold count against the threshold.
- A New Review Workflow: reaching a suggestion's "I Won't Watch" threshold no longer retires it automatically. It's immediately removed from nominee eligibility, its status becomes the new ⚠️ **Pending Crew Review**, its "I Won't Watch" button is disabled, and the configured Admin Channel is notified naming the suggestion, its collection, the current rejection count, and who voted "I Won't Watch". The notification offers **Retire** (permanently retires it), **Keep Active** (restores Available status and clears every recorded rejection), **Reset Rejections** (same effect, kept as a separately labeled action), and **View Suggestion** (links back to the original post) -- all WASH-Crew-only. Pending Crew Review joins the suggestion status model, shown consistently in `/list`, `/database health`, and every status display; it's never a directly settable status. The notification's buttons are fully persistent, like every other interactive control in WASH -- they continue working after a bot restart (reconnected to the correct suggestion, rejection records, and collection), without ever posting a duplicate notification or re-arming an already-resolved review, and a deleted notification message or channel is skipped gracefully at restart rather than failing startup.

### Changed

- **Filter menu UX polish** (no change to filtering behavior): every filter editor (Genre, IMDb Rating, MPAA Rating, Actor, Member) now offers the exact same **Clear Filter** button, replacing five differently-worded resets ("Any Genre"/"Any IMDb Rating"/"Any MPAA Rating"/"Any Actor"/"Any Member" as separate buttons or a special first select option) with one consistent, identically-styled action that clears only the filter being edited and returns immediately to a refreshed menu. MPAA Rating's picker now matches Genre/Member's own shape (a plain dropdown that can be left blank) instead of carrying its own inline "Any MPAA Rating" option. The Current Filters summary (shown identically by both `/random watch` and `/vote start`'s Customize This Vote) is now a dot-leader-aligned block (e.g. "Genre .......... Sci-Fi") instead of a bulleted "Label: value" list, for easier scanning. Three buttons were renamed for brevity/consistency: "Set Minimum/Maximum..." -> **Set Rating Range**, "Search for an Actor..." -> **Search Actor**; the IMDb Rating modal's fields are now explicitly labeled "Minimum IMDb Rating"/"Maximum IMDb Rating". The Random Watch result embed's footer now reads "🎲 Picked at random with /random watch" (previously "Selected randomly by /random watch"). The shared `filter_menu_view.py` module remains fully generic and is expected to be reused with minimal changes by the planned `/browse` command.
- `/random_watch` is now `/random watch`, a grouped subcommand (pre-release, no compatibility alias kept) -- consistent with `/voting`, `/database`, and `/watch-party`'s own grouped commands. Behavior, permissions, and every custom control are otherwise unchanged.
- `/config`'s main menu dropdown no longer shows description text under any option (previously only Voting Defaults did, explaining Visible/Blind) -- it's now a clean numbered list of section names only. The Visible/Blind explanation moved to the Voting Defaults screen itself, alongside its new Nominee Selection dropdown (see Added, above).
- "I Won't Watch" threshold is no longer bundled into the Setup Wizard's Voting Defaults modal or `/config`'s per-collection "Rejection Settings" submenu item -- both now live entirely in "I Won't Watch" Settings' own dedicated step/section (see Added, above). The per-collection settings menu (`/config` -> Collections -> [Collection], and `/database manage`'s Edit Collection) still shows the collection's current "I Won't Watch" status for reference, but editing it now happens only from the dedicated section.
- **Breaking, pre-release command restructuring** (WASH has not yet been publicly released, so no compatibility aliases were kept): `/start_vote`, `/vote_status`, and `/edit_vote` are now `/voting start`, `/voting status`, and `/voting edit`. `/database_add`, `/database_list`, `/database_backup`, `/database_restore`, `/database_reset`, and `/database_remove` are now `/database add`, `/database list`, `/database backup`, `/database restore`, `/database reset`, and `/database remove`. `/schedule_watch_party`, `/reschedule_watch_party`, `/cancel_watch_party`, and `/watch_party_status` are now `/watch-party schedule`, `/watch-party reschedule`, `/watch-party cancel`, and `/watch-party status` -- hyphenated to stay distinct from the pre-existing, unchanged `/watch_party` (underscore) Watch Party *membership* administration group. `/about`, `/add`, `/backup`, `/config`, `/help`, `/list`, `/restore`, `/setup`, and `/stats` remain top-level, unchanged.
- `/database add` is now an interactive, modernized flow instead of a single `name` parameter: it first offers a collection-type choice -- every standard type (Movies, TV Shows, Anime, Holiday, Documentaries, Horror) this server doesn't already have a matching collection for, plus Special Collection and Custom, which are always available -- then the same Create New Thread (Recommended)/Use Existing Thread/Use Existing Channel destination choice `/database move` (below) uses, and persists the new collection immediately.
- The Setup Wizard's Collection step now shows **Create New** before **Select Existing**, and **Create New** (rather than **Select Existing**) uses the recommended/highlighted button style, reflecting that creating a new collection is the more common first-run path.
- Every duration field's helper text is now standardized to the compact examples "10m, 1h, 7d" (superseding the previous "10m, 1h, 1d, or 1w" wording -- see the Duration UX Standard entry below). The Voting Defaults and Reminder Defaults modals now prefill and redisplay saved durations in this same compact form (e.g. `1d` instead of "1 day"); human-readable output elsewhere (confirmations, summaries) is unaffected.
- **Duration UX Standard**: every duration field now presents the same way -- a label naming its actual valid range (e.g. "(1m-30d)" where that range applies; omitted for fields like Shorten/Extend Vote's Custom Duration that have none) plus the three official examples `10m`, `1h`, `7d` (never both a `1d` and a `7d` example, and never a `1w` example). Fields whose Discord modal always has a value (so their placeholder would never actually be shown) now put the range and examples directly in the label instead, kept within Discord's 45-character label limit. `w`/`week`/`weeks` continue to parse exactly as before -- this is a presentation change only, not a change to what's accepted.
- User-facing text now says "server" instead of "guild" (e.g. "Choose the server's default..."). Internal code, persisted field names, and developer-facing documentation are unchanged.
- `/edit_suggestion` no longer exposes OMDb-derived fields (title, release year, IMDb link) for manual editing -- it now presents Change Status, Move to Another Collection, and Cancel actions, with IMDb metadata shown read-only for reference.
- Every "leave blank to use the configured default" prompt (in `/voting start`'s Customize This Vote modal) now also names the actual configured value, e.g. "Leave blank to use the configured default (Visible)".
- The duplicate-suggestion warning for an active match now reads "🔴 That title is already in this collection." (previously "That title is already on the list."), and its reference is labeled explicitly (e.g. "Reference #0007").
- `/list`'s Watched status filter is now Vote Winner, matching the new status model.
- The "Watched Movie Destination" setting (Setup Wizard, `/config`, and its per-collection override) is now called the **Watched Item Archive** everywhere, with wording clarifying its actual purpose: archiving completed watch items (Vote Winners and Retired items) together with links back to their suggestion and voting history -- not a discussion or general watch-history channel. No underlying field names or persisted data changed; existing configured channels/threads carry over unchanged under the new label.
- `/add`'s slash-command description now reads "Suggest a watch item by title or IMDb URL." (previously "Suggest a watch item.").
- The suggestion message's green **Watched** button is now labeled **Mark as Watched** (it's an action, not a status indicator) everywhere it appears -- its post-confirmation disabled state keeps the past-tense "✅ Watched" label, since that's reporting a completed fact rather than inviting an action.
- The suggestion message's **I WILL NOT WATCH** button is now labeled **I Won't Watch** (shorter, same meaning) everywhere it appears, including its rejection-count display (e.g. "I WON'T WATCH: 1 / 2") and every reference to it in documentation. While a suggestion is Pending Crew Review, the disabled button now reads "Review Pending — I WON'T WATCH" (previously a two-line "I WON'T WATCH\n(Disabled)", which Discord always renders as one line regardless).
- **Release UX & Command Surface Cleanup:** `/database manage`'s action menu is now ordered administrative actions first, destructive actions last (**Edit Collection**, **Backup Collection**, **Move Collection**, **Restore Collection**, then **Reset Collection**/**Remove Collection**), rather than leading with Move Collection.
- Every place WASH asks for a vote/reminder duration now makes minutes/hours/days more obvious. Where a field is pre-filled (Setup Wizard's/`/config`'s Voting Defaults and Reminder Defaults modals), Discord's 45-character label limit left no room for both the valid range and examples, so the label now names only the field and its range (e.g. "Vote duration (1m-30d)") and the fuller explanation ("Durations combine a number with a unit -- minutes (m), hours (h), or days (d). Examples: 10m, 1h, 7d.") moved to the screen shown immediately before the modal opens. Every already-blank field (Customize This Vote, `/vote edit`'s Shorten/Extend Vote Custom... option) is unchanged in shape but now shares the exact same canonical example text (`services/duration_parser.DURATION_FORMAT_EXAMPLES`) as every other duration field, and `/vote edit`'s Shorten/Extend Vote quick-pick screen now also explains the Custom option's format up front. The accepted syntax itself is unchanged.

### Removed

- **Release UX & Command Surface Cleanup:** `/database move`, `/database backup`, `/database reset`, and `/database remove` are no longer separate top-level slash commands (pre-release, no compatibility alias needed) -- every one of those actions is fully reachable through `/database manage`'s guided picker-then-menu workflow instead, with no functionality lost; their underlying logic (`start_database_move`/`backup`/`reset`/`remove`) is unchanged and still fully tested. `/database`'s top-level surface is now `add`, `list`, `health`, `manage`, and `restore` -- `/database restore` is the one action that must remain a direct command, since Discord has no way to attach a file upload in response to a button or modal interaction. `/database health` was added to `/help`'s Collections section, which was previously missing it.

### Fixed

- A Balanced Random (Rotation Pool) collection with plenty of "Available" suggestions could still fail `/voting start` with "not enough eligible suggestions" when most of them were on Rotation Cooldown from a recent round -- the rotation only rolled over once every assigned suggestion reached a terminal state, even when it could never supply enough candidates for the requested vote size. `/voting start` now rolls the rotation forward automatically whenever the current one can't satisfy the request (but never when it already can, and never when rolling over wouldn't help), returning previously-presented suggestions to eligibility and refreshing their confirmation posts back to 🟢 Available in the same step.
- The suggestion thread/channel `/setup` creates for a new collection is now immediately saved as that collection's Suggestion Destination, so `/add` works right away instead of reporting no suggestion channel is configured.
- A losing vote candidate's public confirmation post now updates to 🟡 Rotation Cooldown when its round completes, matching the winner's post updating to 🟣 Vote Winner -- previously only the winner's post was refreshed, leaving every losing nominee's post stuck on its prior status indefinitely.
- The Setup Wizard's chosen home channel (Requirement 4) is now actually persisted across a Save & Finish Later + resume -- it was previously missing from the wizard's saved-state serialization entirely, so resuming a paused setup silently lost the choice and later failed with "WASH's home channel is no longer available."
- The Setup Wizard's final save could fail silently and leave the guild in an inconsistent state: an unexpected persistence error (rather than a validation issue) was never caught, so it could report false success, mark the guild's configuration complete without every part of it actually being saved, and block `/setup` from ever being resumed to fix it. The final save is now staged so the guild-wide configuration record (and the one flag every other command gates on) is only ever written once every other part of the save has already succeeded; any failure -- expected or not -- keeps the wizard open with every entered value intact, shows a clear "could not be saved" message, and lets the WASH Crew member retry without repeating any step or recreating any channel/thread/collection. `/config`'s Voting Defaults, Reminder Defaults, and Backup Defaults sections likewise show an actionable message instead of erroring if their configuration is ever unexpectedly missing.
- Setup Wizard Step 6 (Watched Item Archive) now recommends **Create New Thread**, consistent with the "create a new one" recommendation already used on the Home Channel and Collection steps, without forcing thread creation over an existing destination or skipping.
- Reminder Defaults' "should a reminder be sent?" question is now an **Enable**/**Disable** button choice (in both the Setup Wizard and `/config`), not a free-text yes/no modal field -- Disable now skips the lead-time modal entirely instead of still asking for one.
- `/add`'s duplicate-suggestion warning no longer exposes a raw, unlabeled IMDb URL inline -- it now shows a labeled `[Original Suggestion](link)` link to the original Discord message instead (the IMDb preview card already covers IMDb linking), gracefully omitted for a legacy suggestion with no recorded message reference.
- A Reminder Defaults duration-syntax error message was missing the `1w` example every other duration field's error already showed.
- A validation failure at Save (e.g. WASH could no longer post in the previously selected Admin Channel) correctly redirected to the failing step, but fixing it there then forced every later step to be walked through again instead of returning to Review -- both this and Review's own "edit a section" dropdown now return straight back to Review once the one corrected value is re-answered, with every other value (earlier and later) left exactly as it was.
- Channel/thread permission-failure messages (Admin Channel, Watch Destination, and their `/config` equivalents) now name the channel directly and say exactly which permission(s) to grant (View Channel, Send Messages), suggest choosing a different channel, and suggest creating a new one, with an added reminder about private-channel access and role hierarchy when relevant -- never suggesting the Administrator permission, and never including raw exception details.
- The Setup Wizard's Admin Channel step now explains, up front, that a private channel only appears in the destination picker once WASH has been granted View Channel and Send Messages on it, and that reopening the step refreshes the list -- previously an administrator with a private channel WASH couldn't yet see had no indication why it was missing.
- The "what type of collection" and "select an existing collection" nested screens (under the Setup Wizard's Collection step) previously offered **Cancel Setup** only, making a full destructive cancel the only way to exit safely -- both now also offer **Back** (returns to the Collection step) and **Save & Finish Later**, matching every other setup screen.
- The Watched Item Archive step's (and its `/config` equivalents') destination picker could omit threads created earlier in the same setup session after navigating back to it -- destinations are now rebuilt fresh on every render directly from the guild's current channels and active threads, labeled with parent-channel context (e.g. "watch-party › watched-items"), excluding archived/locked/inaccessible threads, and always showing the previously saved destination pre-selected.

## [1.0.0] - 2026-07-24

Watch Party Manager's first complete, self-hostable release: a Discord bot (**WASH**, the Watch Party Administration & Scheduling Helper) that runs a community's entire watch-party lifecycle -- suggesting titles, voting, scheduling, and reporting on the results -- through guided setup rather than manual configuration file editing.

### Added

**Foundation**

- Core domain models: `WatchItem`, `WatchItemJourney`, `SuggestionDatabase`, `VoteRound`/`VoteRecord`, `GuildConfiguration`, `Rotation`, `WatchParty`, and `MembershipRequest`, each with its own validation and a dedicated JSON repository.
- A layered architecture separating domain models, persistence, Discord-agnostic services, and thin Discord command/view code, enabling the test suite to exercise business logic independently of Discord.

**Suggestion Management**

- `/add`, `/list`, `/edit_suggestion`, and `/remove` for the full suggestion lifecycle, plus `/repair_suggestions` for correcting malformed legacy entries.
- IMDb link normalization (accepting common URL variants and storing a canonical form) alongside plain-title suggestions -- no IMDb link is ever required.
- Duplicate detection distinguishing definite duplicates (matching IMDb ID or title-and-year) from possible duplicates (matching title, unknown year), checked against active, archived, and watched items.
- Re-suggestion rules: active duplicates are always blocked; archived, rejected, or previously-watched matches require WASH Crew confirmation to reactivate rather than creating a second record.
- Archive-preferring removal: `/remove` (and the automatic rejection-threshold path) archive a suggestion rather than deleting it, preserving its history and reference number.
- Public confirmation posts announcing a newly added or reactivated suggestion in its database's configured channel.
- Stable, zero-padded reference numbers (`#0007`) for every suggestion, usable when removing, editing, or looking up statistics.

**Multi-Database & Guild Configuration**

- Guild-scoped suggestion databases (`/database_add`, `/database_list`, `/database_remove`), each tied to its own Discord channel or thread and independently configurable.
- Per-database configuration covering suggestion rules, voting overrides, notifications, permissions, archive behavior, and watch-history settings.
- Guild-wide configuration (roles, channels, voting defaults, notifications, feature flags, backup schedule) persisted independently of environment variables.

**Setup Wizard & Configuration**

- A guided, fully re-runnable `/setup` wizard covering the WASH Crew role, the Watch Party role and join mode, suggestion database selection or creation, watch-history destination, voting defaults, reminder defaults, and backup defaults, ending in a save/edit/cancel summary.
- `/config`, an always-available menu mirroring the wizard's sections for making individual changes afterward without repeating the whole flow.

**Voting System**

- `/start_vote` with a choice of guild-configured defaults or per-round customization (nominee count, duration, visibility).
- Blind and visible voting, selectable per round or as a guild default.
- Interactive Discord voting posts with numbered vote buttons, vote changes within a configurable limit, and persistent restoration of every interactive control after a bot restart.
- Deterministic standings and winner calculation with tie support, plus `/vote_status` and WASH Crew's `/edit_vote` (change end time, end early, or cancel).
- Fully automatic vote completion: expiration, closing, winner announcement, and Watch Item Journey updates, driven by a persistent scheduler rather than requiring a WASH Crew member to close a round manually.

**Candidate Selection & Rotation Management**

- Configurable candidate-selection strategies per database: Rotation Pool (the default, excluding a suggestion from selection once presented until a fresh rotation begins), Soft Rotation (weighting presented suggestions lower without excluding them), and Infinite Pool (no rotation restriction at all).
- Persistent rotation lifecycle tracking -- assigned, presented, remaining, retired, and watched counts, with completion percentage -- and automatic transition to a fresh rotation once one is exhausted.
- Configurable admission for newly added suggestions: join the next rotation (the default) or expand the current one immediately.
- A distinct "retired" lifecycle for suggestions archived via the "I WILL NOT WATCH" rejection threshold, separate from WASH Crew-initiated archival.
- An optional Low Pool Reminder that nudges a channel when a database's active suggestion count falls below a configurable threshold, rate-limited to a configurable minimum interval.
- Genre- and media-type-diversity-aware nominee selection that deprioritizes (without ever permanently excluding) recently nominated or recently won suggestions.

**Statistics & Reporting**

- `/stats` with server, member, suggestion, rotation, and database views, all recalculated from historical data on every request rather than maintained as running counters.
- Server statistics covering watch parties, voting rounds, blind/visible and tie counts, average participation, average candidates per round, and average vote duration.
- Per-suggestion statistics: created date, submitter, nomination history, watch/retirement status, and rotations participated in.
- Per-member statistics restricted to the requesting member's own history (suggestions submitted/watched/retired, votes cast, participation percentage, winning suggestions) -- no one, including WASH Crew, can retrieve another member's personal statistics.

**Backup, Restore & Import**

- `/backup` and `/restore` (selecting an existing local backup or uploading one) for a full server snapshot, with pre-restore validation, a change summary, and confirmation before anything is overwritten.
- Automatic safety backups before every destructive operation.
- Per-database `/database_backup` and `/database_restore` (merge or replace), plus `/database_reset` and a fully typed-confirmation-gated `/factory_reset`.
- `/import`, for merging or replacing data from another WASH instance's backup archive, with conflict reporting.

**Permissions, Roles & Membership**

- Two-tier, fail-closed role permissions: WASH Crew (administrative) and Watch Party member (participant), with WASH Crew automatically inheriting member permissions.
- Four Watch Party join modes -- Self-Service (`/join_watch_party`), Manual, Approval-Required, and Discord-Managed -- plus `/watch_party` for WASH Crew to list, approve/deny, manually add or remove, and search membership history.
- Ephemeral-by-default command output throughout, with WASH Crew able to post eligible results (suggestion lists, statistics) publicly, and members able to publicly post their own statistics.

**Scheduling**

- A persistent, restart-safe job scheduler driving automatic vote closing, vote-ending reminders, and watch-party reminders.
- Scheduled watch parties (`/schedule_watch_party`, `/reschedule_watch_party`, `/cancel_watch_party`, `/watch_party_status`) with configurable reminders.

**Help, About & Diagnostics**

- A structured, permission-aware `/help` registry showing each member only the commands they can use, linking out to expanded GitHub-hosted documentation.
- `/about`, reporting version, build, Discord gateway latency, and uptime alongside a feature summary.
- Startup data-integrity checks and structured application logging throughout.
